# 外业规划 FP0–FP1：本地草稿验收

日期：2026-10-08。范围：FP0 数据契约与基线、FP1 用户自有任务保存。**本记录的本地工程验收通过，不代表现场可通行或已可公开发布。** 后续 FP2 的 2026-10-09 状态见 [FP2 进度](ROADOPS_FIELD_FP2_PROGRESS.md)，不改写本记录的历史验收范围。

## 1. 已交付与操作入口

驾车面板新增“任务草稿”，保留现有蓝字/浅蓝底和可调整宽度的抽屉。

1. 选择自己的起点、终点、途经点，填写任务名称，首次点击“保存草稿”。首次保存前不自动建立记录。
2. 已保存任务的修改在停止输入约 800 ms 后自动保存；等待“已保存 · vN”后再离开。关闭/刷新时尚未保存会请求浏览器显示离开提醒，提醒是否显示受浏览器策略影响。
3. 刷新或重新打开后，在“恢复与备份”选择任务 →“恢复所选”→ 查看替换提示 →“确认恢复”。不自动选中/恢复最后一次任务，不自动算路。
4. “另存为新草稿”建立独立方案；“新建行程”只清空编辑区，不删除已有草稿。原有“清空”会提示它可能把当前已保存方案更新为空行程。
5. JSON 导入校验后预览任务/点位数量和时间差异，明确确认后创建新 planId，不覆盖原计划；taskId / stopId / visitId 保留。
6. JSON 导出默认不含核验备注；勾选后才包含。名称与精确坐标始终在任务备份内，不含照片文件、地图商折线、时距、路况、完整响应或密钥。
7. 删除只针对所选任务和所选修订，需明确确认；不清空数据库或删除原照片库。未留备份的草稿删除后不能恢复。

**修订号是并发写入保护，不是可回滚的历史版本库。** 需要保留某版时先另存或导出。出现异常时保留当前输入、暂停自动保存，可导出或另存，不自动覆盖/重置存储。

本轮临时验收地址：[无密钥草稿测试页](http://127.0.0.1:4193/map?demo=road)。只监听本机，进程存活时可用；不能生成真实路线。原 4192 地址在本轮检查时未监听，未擅自重启带 Key 服务或重置它的用量。

## 2. 数据与兼容边界

- `field-task-plan-v1` 固定 WGS84 `[经度, 纬度]`，分离任务、车辆停靠和到访实例，最多 20 个任务、6 个中途到访、含起终 8 个到访。v1 编辑器仍是一点一任务，起终点也计入兼容记录数，不代表完成了对应实地核查。
- 保存字段：点名、目标/独立车辆坐标、顺序、策略、停留、出发时刻、可用工时、缓冲、原人工状态与备注；工时 30–720 分钟、缓冲 0–720 分钟。未选坐标可保存为待完善草稿。
- 契约已能表示返程和共站，但当前编辑器不能无损表达时明确拒绝恢复；日期排程、可延期、起点核查耗时、空独立车辆坐标等不支持的语义也不静默丢弃。不能把契约样例当成已实现 FP2/FP4。
- 任务 ID 与现有驾车请求的 80 字符/字符集约束兼容；保留 `vehicle:` 选点前缀，不重写不兼容的导入身份。新增途经点使用独立 ID，不复用删除点位的编号；已有草稿身份不迁移。
- 恢复旧 `confirmed` 时降为 `unknown`，备注加“历史确认待补充”；`blocked` 不因恢复变成允许。结构化核验人、时间、依据和期限留待 FP3。
- IndexedDB 独立库 `lanjifyw-field-task-plans-v1`，事务提交后才显示成功。原 `lanjifyw-field-observations` 照片库不修改、不复制；任务与照片的结构化关联留待 FP3。
- 同一 readwrite 事务内核对 expectedRevision，再写入/删除。BroadcastChannel 仅用于及时提示，通知不可用时仍由数据库事务防覆盖。等待读取/导入期间输入改变，则不替换新输入。
- 本地存储按 origin 隔离；端口、浏览器、设备变化及清理存储可能使记录不可用。不是账号同步、账户隔离、加密保险箱或可靠备份；请勿在共用浏览器录入不应共享的敏感资料。
- 坐标/车辆到达点/顺序/策略变化使旧路线失效；停留/备注/工时变更沿用既有本地重评估。恢复无条件清除旧供应商结果和地图选点状态，需要另行手动生成路线。
