## 1. 目标、现状与不可越过的边界

目标：形成“制定核查任务 → 安排车辆停靠与访问顺序 → 记录进入核验 → 出发前复核 → 现场记录 → 返回后复盘”的单车单日流程。

现有基础可以复用：滴图真实逐段道路几何、手动地图选点、行驶方向、目标/车辆到达点分离、停留与超时提示、人工禁入阻断、TXT 任务单、已有照片与 InSAR 关联。本方案不重建地图引擎，也不把 OSM 质检演示重新设为驾车输入。

| 边界 | 执行约束 |
| --- | --- |
| 产品范围 | 普通小客车、单车、单日、少量核查点。先保留最多 6 个中途到访；拟定每计划最多 20 个核查任务，FP0 固定校验常量。返程不额外扩大规模。多车、多日、大规模任务分配另立需求。 |
| 地图与算路 | 沿用现有平台、Leaflet 和滴图驾车 Web Service。OSM 是可选显示底图或有来源的专题数据，不参与替代滴图寻路。 |
| 界面范围 | 保留现有导航、卷帘抽屉与蓝字/浅蓝底选择态，新增复杂字段渐进展开；不在本轮重做全站视觉。 |
| 暂不接入 | 步行、骑行、公交 API；地图商 JS API；自研语音/逐转向导航；后台定位与持续轨迹采集。最后一段可人工记录方式及耗时，不生成假步行路线。 |
| 数据事实 | 用户目前没有额外封路、入口、停车资料。缺失是“未知”，不是“畅通”。路线存在、道路偏移小、无风险命中均不等于现场可进入或安全。 |
| 真实请求 | 仅用户明确触发。保留本地 100 HTTP 尝试/天、1 QPS、自动重试 0；不得通过重启或更换浏览器绕过保护。HTTP、packs、官方额度/账单分别记录。 |
| 数据持久化 | 用户自有任务与地图商结果分开。未核清许可前，不新增供应商几何、时距、路况等返回/派生数据的持久化或打包导出；现有使用方式也不能当作已获授权。 |
| 隐私 | 默认本机存储；备注、联系人、照片、EXIF 不随算路请求发送。不承诺本地存储已经具备账户隔离、加密备份或跨设备同步。 |
| 安全判断 | 确定性距离、预算、时窗、状态由代码处理。AI 不作为进入许可、道路安全、封路和路线有效性的裁决者；本轮不增加 AI 调用。 |
| 发布 | 实施阶段原边界是不推送、不部署、不自动开放局域网或公网；2026-10-09 单独授权Vercel代码发布及后续受保护驾车接通已完成，无Git推送。其余未完成业务/许可门禁仍保留，不自动配置其他Key或扩展公共服务。非商业用途不免除数据许可、隐私与地图服务适用要求的核查。 |
| 实地操作 | 计划只供辅助；驾驶中不操作页面。不得为验证软件而进入禁入区、风险区或缺少必要许可的现场。 |

以下 50 米偏移、100 米关联半径、30 分钟路线复核时间，以及后续核验有效期，均属可解释的产品规则，不是法定安全标准。

## 2. 阶段总览与完成口径

| 阶段 | 交付结果 | 主要解决的问题 | 难度 / 外部依赖 |
| --- | --- | --- | --- |
| FP0 | 冻结基线、契约与测试样例 | 历史演示和真实路线混淆、边界不清 | 低；无需新增资料 |
| FP1 | 自有任务草稿、版本和备份恢复 | 刷新丢失、不可继续使用 | 中；无需滴图 Web Service 请求 |
| FP2 | 返回驻点、多个任务共用停车点 | 起终点重合被拒、任务与坐标绑定过紧 | 中高；真实算路验收有独立门禁 |
| FP3 | 结构化进入核验、逐站任务记录 | 核验不可追溯、规划和现场照片脱节 | 中；事实由用户录入，缺资料仍可开发 |
| FP4 | 显式刷新、持久额度、单日约束排程 | 旧缓存被误当最新、排程不体现实际限制 | 中高；未来 ETA 为条件扩展 |
| FP5 | 真实几何空间关联、覆盖与时效说明 | 滑坡中心近似、前 200 条漏检 | 中高；真实风险效用依赖资料 |
| FP6 | 本地综合验收、有限试用及发布清单 | 工程通过被误当可实地执行或可公开发布 | 中；真实调用/试用/发布分别确认 |

依赖：FP0 → FP1 → FP2 → FP3 → FP4 → FP5 → FP6。FP5 的几何单元测试可与 FP4 并行，但最终报告须共用稳定的任务/到访契约。

该顺序按工程门推进。FP0–FP3 的新增真实服务门暂不执行，统一在 **G4-02 的持久化额度保护通过后**进入 FP6B；早期阶段可标“工程门通过、真实服务待验”，不阻塞其余无网络开发。

首个可交付里程碑为 FP1–FP3：任务不丢、往返合理、核验与现场记录可追溯。第二个里程碑为 FP4–FP5：排程与数据关联能力增强。两者都不等于导航系统或安全认证。

每个阶段分别记录：

- `工程门`：单元、契约、异常、回归与 UI 验收。
- `服务门`：如需真实滴图，记录实际请求与控制台增量；mock 不能替代。
- `业务门`：人工操作及现场事实验证；没有现场数据不得勾选通过。
- 状态使用 `待执行 / 通过 / 未通过 / 待外部条件 / 不在本期`。不得用“部分功能完成”覆盖未通过门槛。

## 3. 先固定数据模型，避免反复改接口

以下为分阶段契约：FP0/FP1 已落地 FieldTaskPlan、InspectionTask、VehicleStop、VisitOccurrence 的首版及 v1 导航适配；AccessCheck、ExecutionRecord 和供应商快照扩展仍待后续阶段，不表示已实现完整表中功能。

| 对象 | 最小字段与职责 |
| --- | --- |
| FieldTaskPlan | planId、schemaVersion、revision、名称、日期、时区、起终方式、策略、创建/更新时间；组合任务、停靠点和到访序列。 |
| InspectionTask | taskId、目标坐标/坐标系、任务说明、必访标记、核查耗时、原始证据引用；不同核查任务永不因同坐标而被删除。 |
| VehicleStop | stopId、车辆到达坐标/坐标系、入口/停车说明；共用必须显式关联，同经纬度不自动视为同一侧道路或同一入口。 |
| VisitOccurrence | visitId、stopId、taskIds、访问序号；同一驻点出发和返回有不同 visitId，同一物理 stopId 可重复使用。 |
| AccessCheck | 核验维度、对象 ID、坐标版本、状态、核验人、核验时间、依据、有效期/复核期限、证据引用。 |
| ExecutionRecord | planId、计划版本、visitId、taskId、执行状态、实际时间、原因、照片/观察记录 ID；更正保留历史。 |
| ProviderRouteSnapshot | 算路输入指纹、生成时间、请求模式、来源、分段结果和使用边界；与自有草稿分离，持久化/导出由许可白名单控制。 |

访问示例：驻点 S0 的 V0 → 停车点 S1 的 V1（任务 T1、T2）→ 驻点 S0 的 V2。路段关联 V0→V1、V1→V2，不能只以 stopId 作为唯一键。

迁移策略：现有 NavigationDraft 的每个点先转成独立任务/停靠/到访；现有人工确认因缺结构化核验信息，保留原备注并标记“历史确认待补充”，不得直接升级。旧照片库保留，优先新增关系表，不搬迁或复制全部照片。

## 4. FP0 — 基线与边界冻结

### 实施内容

1. 清点当前功能、构建产物与旧 Phase 演示入口；记录当前文件版本/哈希及脏工作区，不擅自提交、回退或覆盖用户修改。
2. 确定上一节模型、旧 v1 请求兼容策略和新版本响应解析规则。改动消费者清单须包含请求校验、报告、地图标记、React key、导出与测试。
3. 建立纯本地模拟样例：普通单程、返回原地、三个目标共用停车点、道路方向不对称、不可达、入口未知/禁入、超时窗、过期资料、存储损坏。
4. 对真实调用单列前置项：密钥仅服务端、历史暴露密钥轮换确认、当日账号用量、`packs` 计量口径、显示与缓存权限。不能核实时继续 mock 开发，不发真实请求。
5. 确认本地服务启动方式与健康检查。当前本轮不启动服务；后续按实施请求恢复本地服务也不得因此自动算路。

### 验收门

- **G0-01**：空白页面、选点、拖图、恢复草稿均为 0 次滴图 Web Service 请求（包括转换、矩阵、驾车）。底图瓦片仍可按图源政策加载；这类流量单列，不混入本地滴图 100 HTTP 账本，也不宣称页面零网络请求。
- **G0-02**：模拟数据明确标记“测试/模拟”；供应方失败时不显示模拟沿路结果冒充成功。
- **G0-03**：建立问题—阶段—验收 ID 对照；发布与真实调用前置项可以处于待外部条件，不影响无网络测试。

边界：不承诺本阶段完成用户登录、公共部署或实际通行验证。

## 5. FP1 — 自有任务保存、恢复与版本

### 实施内容

1. 新增带 schemaVersion 的 IndexedDB 任务存储，与现有现场照片存储解耦；草稿更新采用事务和修订号，处理多标签页冲突。
2. 提供新建、另存方案、恢复、明确确认后的删除，以及可见的“保存中/已保存/保存失败”。有存储错误时保留当前内存内容并提供导出，不显示假成功。
3. 提供自有任务 JSON 导入/导出：只含白名单字段；校验结构、坐标、数量、大小、重复 ID、引用完整性和版本；导入前预览差异，不覆盖现有任务。照片引用缺失须提示，不伪造附件存在。
4. 输入修改划分为三类：路由几何失效（车辆坐标/顺序/策略）、本地排程更新（停留等）、核验失效（入口/相关坐标/期限变化）。恢复不自动调用滴图 Web Service。
5. 未核清地图商许可前，恢复的是用户任务草稿，不保证恢复供应商折线/时距；界面明确“需手动生成/复核路线”。禁止将旧生成时间替换为恢复时间。

### 验收门

- **G1-01**：同一浏览器、同一 origin 刷新及重开后，任务、坐标、顺序、时间和备注保持一致；恢复时上游计数不变。
- **G1-02**：模拟配额满、事务失败、私密模式限制、损坏 JSON、未知新版本，均有明确处理；原任务和原照片库不受损。
- **G1-03**：两标签页同时编辑不会静默互相覆盖；修改坐标后旧路线不能继续作为当前方案。
- **G1-04**：导出再导入保留任务身份；不包含密钥、供应商完整返回或未勾选的私人备注。

回退：通过入口开关禁用新存储；保留新旧记录，不能删除存储来“修复”失败。

边界：IndexedDB 不是可靠备份。更换端口、域名、浏览器或设备不保证能访问原数据；浏览器清理也可能丢失记录。需配套备份说明。[MDN 存储说明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

## 6. FP2 — 返程与共用停车点

### 实施内容

1. 增加“单程/返回出发地”。返程末次到访复用驻点位置，但采用独立访问实例，保留真正返程路段及其时间。
2. 增加“关联至已有停车点”，显示该停靠包含哪些任务。只在用户确认共享同一车辆停靠位置、并在同一次到访处理时合并；相邻地点、道路两侧和入口不能自动归并。
3. 请求只对需驾车移动的物理停靠位置算路；同站任务之间不请求虚假的零距离驾驶段。保留每个任务的目标、耗时、核验及完成状态。全程仅一个停车站的任务明确为“无需站间驾车”，不冒充滴图已生成路线。
4. 同步调整 v1/v2 适配器、响应解析的唯一性判断、field 报告的起点停留规则、路线段 ID、地图序号/弹窗、导出。不能只放开坐标重复校验。
5. 保留有向时距，AB 与 BA 分别校验；到达与离开吸附位置不同、疑似隔离带/路侧不一致时保持待复核，不能画连接短线冒充可通行。

### 验收门

- **G2-01**：A→B→C→A 的首末坐标相同而访问 ID 不同，返程时距计入，所有标记、报告与导出顺序一致。
- **G2-02**：一个停车站关联三个核查任务，不丢任务、不重复计算公共停车时间，也不发送三条站内驾车请求。
- **G2-03**：相同坐标但未确认共用的入口不被静默合并；回到同一地点的不同访问实例可以分别记录执行结果。
- **G2-04**：任一必经道路段失败或缺失，整体方案不得标为可执行；无直线替代、无删点、无伪造坐标。

边界：首期最多 6 个中途到访、含起终最多 8 个到访实例、最多 20 个核查任务；物理站数、访问数、任务数分开校验，共站不能用于绕过请求规模限制。站内任务由用户固定先后顺序，调整后重新核算排程。连续重复且无新增任务的到访由用户确认后消除。新旧路线模块均需回归。

## 7. FP3 — 进入核验与现场任务记录

分两步交付：FP3A 核验结构化，FP3B 逐站执行关联；两步均使用 FP1 的持久化和 FP2 的访问身份。

### FP3A：核验结构化

当前已实现第 1、2、3、5 项的四维人工记录、独立追加历史、期限/坐标守卫及请求双门禁，离线回归通过；第 2 项证据选择、第 4 项分项耗时与完整浏览器操作仍待验/实施，不标记 FP3A 或 G3-01 整体通过。详见独立进度记录。

1. 分开记录车辆接近、停车、入口许可、最后一段进入方式；状态使用“未知/有依据的人工确认/明确不可进入/待复核”。不增加“安全保证”状态。
2. 确认须有核验人（本地自填，不等于已认证身份）、时间、依据来源、适用对象和复核期限；可引用已有照片/现场记录。
3. 入口或相关坐标变化、证据失效、到期后降级为待复核。禁入不能仅因时间到期而变为允许；解除须新增依据并保留历史。
4. 停车耗时、任务核查耗时、最后一段转移耗时分别填写。最后一段数据未知时提示“总耗时尚未完整”，不偷偷按 0 分钟当作完整排程。
5. 地图商道路结果、人工记录、空间风险线索三类来源分栏显示；核验备注不发送给滴图。

### FP3B：执行与证据关联

1. 逐任务支持待执行、执行中、已完成、未完成、延期；未完成/延期必须有原因。已完成需记录结果，照片可选；未到达不能自动视为已核查。
2. 记录实际到达、离开、操作者备注与照片引用。复用现有 FieldObservation；关联 taskId、visitId、计划修订号，不复制二进制照片。
3. 完成状态由用户确认，不以坐标邻近、上传照片或算路成功自动完成。改路线生成新修订，历史执行记录不自动迁移成新站点的完成记录。
4. 增加自有任务打印视图和结构化结果导出，区分内部版与去敏版；导出明确是否含精确坐标、个人备注/照片。去敏版不能宣称完全匿名。
5. 提供目的地名称与明确标注坐标系的坐标复制。导航深链仅在官方协议、目标应用、坐标要求和设备测试明确后作为可选适配；不默认改用高德，不猜滴滴跳转协议。

### 验收门

- **G3-01**：缺核验依据/时间不能显示确认完整；坐标改变、记录过期正确降级；禁入不能被优化忽略。
- **G3-02**：修改一个任务的完成状态不会改变同停车站其他任务；计划修订后照片仍关联原任务/访问，并提示需要重新关联的项目。
- **G3-03**：完成、未完成、延期数量与任务总数口径一致；实际与预计时间分列，不事后改写原计划。
- **G3-04**：网络断开但页面已加载时，用户自有备注/执行状态可本地保存；刷新离线能否重新打开另行验证，未实现应用离线壳时不得宣传完整离线。
- **G3-05**：删除照片/记录时提示关联影响并提供确认；导出可打开、中文正常、无密钥和不允许导出的供应商数据。

边界：未知进入条件不妨碍保存“待核验计划”，但不能显示“核验完成”。明确禁入阻断出发就绪标记。没有新增资料时，可以通过软件状态测试，不能通过真实入口可达的业务门。移动端响应式不等于手机已能访问 127.0.0.1；本期不自动暴露本机服务。

## 8. FP4 — 刷新、额度与单日排程

### FP4A：显式刷新和持久化保护（先做）

1. 区分“复用已有结果”和“重新获取路况”，显示生成时间、缓存命中、估算 HTTP/packs、剩余本地预算；真正刷新使用受控的服务端请求模式，不靠浏览器 no-store。拆开路由与排程指纹，名称、备注、停留和工时等本地变更不应使仍有效的路线缓存失效；未来 ETA 模式下，确实改变分段出发时刻的修改另行标记需重新预测。
2. “按当前顺序刷新”不得偷偷重新优化。需重新优化时显式选择，说明将重新请求矩阵和分段，并生成新修订。
3. 建立本地单服务实例的持久化额度账本：同一上海日期、所有浏览器共用总上限 100；在锁/事务中预留最坏请求数，发出前记账，只释放确定未发送的预留；超时/断网后的已发送请求不退计数。
4. 账本不存密钥/完整坐标/上游 URL；并发启动、损坏或无法读取时阻止新增上游请求并提示处理，不默认为 0。保留 1 QPS、自动重试 0、手动取消及重复点击合并。
5. 刷新失败保留用户草稿。旧供应商结果仅在允许保留范围内作为带原时间的历史参考，不得成为当前成功结果；不可用时只显示错误和用户数据。

当前按序模式通常由一次转换加一次批量算路构成，优化增加一次矩阵请求；未来分批/ETA 扩展可能增加次数。预检必须按实际请求计划计算，不将“永远 2/3 次”写死。一个 HTTP 可能包含多个 packs；官方计量需另行核对。

### FP4B：有限规模、可解释的时间约束

1. 增加计划日期与 Asia/Shanghai 时区、每个任务的服务时间窗、可用工时，以及显式启用的可延期任务标记；默认所有任务仍必访。
2. 统一时长口径：总工时 = 驾车 + 站点停车/准备 + 各任务转移与核查 + 等待 + 分段机动 + 全局应急储备。每项仅计一次；已有“停留”迁移为人工总时长，未拆分前不重复叠加。
3. 时间窗首期定义为“任务服务须在窗口内开始并完成”，提前到达计等待；跨午夜/多日窗口暂不支持并明确报错。全局储备保留在末尾、分段机动进入后续 ETA，两者用途标明。
4. 固定起终点，最多 6 个中途访问时，可枚举至多 720 种访问顺序并做确定性时窗检查；始终基于有向静态成本，计算量边界明确。站内任务按用户给定顺序逐项完成，不假定同时作业；站内窗口冲突也须报出。720 仅指固定访问集合的排列数，首期不自动搜索任务子集。超过上限拒绝或提示拆任务，不自动扩大请求。
5. 先满足必访/禁入/时窗/工时，再在可行解内减少总时长。可延期任务由用户逐项确认延期后形成新任务集，保留排除理由，不能由算法自行删除；在做收益比较时区分“同任务集顺序改善”和“少做任务节时”。自动任务价值选择留作后续需求。
6. 复用同一有效成本快照比较方案，不为每种顺序调用滴图。最终选择的方案仍须逐段取得真实几何并再次检查总时长；不一致时显示需要调整，不无限循环重算。

### FP4C：未来 ETA（条件扩展，默认不启用）

官方模型已有 departure_time 与 eta_strategy=3；不能称“滴图不支持未来时间”。但预测覆盖、权限、单位、请求规模和准确性需独立验证。[滴图响应模型 PackReq](https://lbs.xiaojukeji.com/docs/web/guide/响应模型.html)

仅在资料与真实契约验证充分后，为选定顺序按预计分段出发时间进行有限次数校正；缓存键包含时刻、预测模式与时区转换结果，预设最大迭代和最坏预算。没有权限/证据时保留 FP4B 的“当前路况快照排程”，不显示“明日预测”。预测也不是保证准点。

### 验收门

- **G4-01**：相同方案复用为 0 新增 HTTP；显式刷新能够绕过服务端结果缓存；取消、失败和超时均不自动重试。
- **G4-02**：重启、两标签页并发、剩余额度不足、跨日及账本损坏用 mock 验证，不超过 100 次本地日上限；已发出请求不因客户端取消而漏计。
- **G4-03**：构造提前到达、窗口关闭、核查时间超窗、返程超工时、必访不可达和可延期候选；输出正确可行性或明确冲突，不偷偷删必访任务。
- **G4-04**：同站多任务的核查/转移、共同停车、等待与机动没有漏算或双计；共站三个任务具有不同时间窗时，调整站内顺序能得到对应的可行性变化，不能按并行处理；时刻字段与 UI/导出一致。
- **G4-05**：同任务集、同成本快照对比基线，优化效果可复算；在相同约束下无改善则保留原可行顺序。精确枚举只称“当前固定任务集、站内顺序和静态模型下最优”，不称现实交通全局最优。供应商错误、矩阵缺失与已确认不可达分开，不将接口失败当作封路。
- **G4-06**：未来 ETA 未验证时保持关闭；如启用，单独记录真实服务门和新增用量，不将普通排程测试当作预测准确性验证。

边界：100 是本地保护配置，不保证其他应用使用同一 Key 后仍有官方余额。生产多实例需要共享事务账本，不能复用单机文件锁宣称全局限额。

## 9. FP5 — 风险空间关联与数据覆盖

### 实施内容

1. 保留原始点/线/面几何及 CRS、来源、采集时间、有效期、精度、许可与数据版本；停止将滑坡面中心作为唯一依据。CRS 未知时暂停精确空间结论，不猜测偏移后“对齐”。
2. 先按路线包围盒/分析走廊和任务范围做空间候选筛选，再做点线距离、线线邻近/相交、线面相交。米制缓冲使用适当投影或可靠地理距离，不能把经纬度差直接当米。
3. 覆盖 Polygon/MultiPolygon、洞、边界接触、退化/无效几何。二维相交不能判断桥梁上下穿越，保持待核验。
4. 替换“按类型排序取前 200 条”为可解释的范围筛选与分批处理；超过本地性能上限时显示已检/未检数量和范围，不默默截断，也不因未命中显示无风险。
5. 分离三类：形变/照片等线索 → 有来源和时效的风险记录 → 有依据的通行限制。即使是权威滑坡风险面，也不自动等同封路。
6. 本期只做风险提示与人工处置。用户确认禁入可阻断就绪状态；不假设滴图支持任意避让多边形。调整停靠点后手动重算，再检查新路线；仍相交则继续提示，不能宣布绕行成功。

### 验收门

- **G5-01**：路线穿过远离面中心的边缘必须命中；路线位于多边形洞内、只触边、跨多个面有明确分类；不伪造禁行结论。
- **G5-02**：超过 200 条、顺序重排的数据不因输入顺序改变已完成范围内的关联结果；未处理范围始终可见。
- **G5-03**：缺时间、过期、演示、CRS 未知、无效几何分别标识；“未发现关联记录”与“没有风险”文案区分。
- **G5-04**：开关风险关联/改变筛选不触发滴图；无额外资料时仍可规划，但报告明确未评估的现场条件。

边界：没有真实合法资料，只能用标明模拟的几何验证算法，不能称真实风险覆盖完成。不批量下载 OSM 道路或影像来填补未知入口，也不向 OSM 回传滴图折线。

## 10. FP6 — 综合验收、试用与独立发布门禁

### FP6A：本地软件验收

按完整场景执行：创建任务 → 保存重开 → 单程/返程与共用停车 → 记录核验 → 生成/刷新 → 查看逐段行程 → 标记部分完成/延期 → 关联照片 → 导出并重新读取。

测试顺序：纯函数与存储测试 → 模拟服务契约 → 静态/服务构建与聚焦 lint → 桌面和 390px 窄屏实际浏览器 → 经批准的小额真实请求。只测源码或 SSR 不代替交互/落盘验收。

可复用的验证入口（执行时以 package.json 为准，本轮未运行）：

```text
npm run test:roadops
npm run test:roadops:navigation
npm run test:roadops:local
npm run lint:roadops
npm run test:roadops:secrets
npm run build:static
npm run build
```

新增任务存储/访问身份/执行/时窗/几何测试须接入上述套件或明确新增命令，不允许测试文件写好却未被运行。全站既有失败单独记录；不得通过扩大忽略范围或跳过断言取得“全通过”。

### FP6B：小额真实服务与有限人工试用

- 初次真实服务验收须先通过 G4-02，再申请总计最多 10 次上游 HTTP 尝试的独立子预算（不是现在授权）。子预算与当日 100 次总保护在同一预留事务中校验，不能只靠人工记数；先估计每个场景 HTTP/packs 并查看官方剩余额度。超预算、权限未知或计费异常时停止。
- 使用经确认可公开测试的位置，不上传私人现场照片或备注；记录前后本地 HTTP/packs 与官方控制台增量，无法取得控制台证据则服务计量门保持待验证。
- 验证按序、返程、共用停靠、缓存复用、显式刷新；限额/超时/并发等破坏性边界全部用 mock，不刷真实接口制造失败。
- 软件门通过后，由用户选择低风险、合法可进入的地点进行有限试用。记录入口偏移、计划/实际耗时、任务完成、未完成原因。驾驶与页面操作分离，不以危险现场验证算法。
- 若暂无出行安排，以桌面演练交付，状态为“本地流程通过，实地未验证”，不虚构现场照片或到访记录。

### 验收门

- **G6-01**：全部必选工程门通过；冷启动、保存恢复、版本变化、导出落盘、网络失败、移动布局有可复核证据。
- **G6-02**：真实接口状态、使用时间、调用增量和限制如实记录；缺一项不能把模拟结果补填为真实通过。
- **G6-03**：任务总数、完成数、延期数、平均耗时等指标有分母；路线节时按同任务集对比，预测与实际分开。
- **G6-04**：产出本地验收报告、未解决项、已验证文件清单及使用说明；部署状态仍为“未发布”。

### FP6C：公开给其他用户使用——另行批准，不能随前面自动完成

公开发布至少满足：

- [ ] 登录、注册、找回流程在目标环境真实可用；服务端鉴权、用户数据/照片隔离、退出后的数据边界经过测试。
- [ ] 浏览器旧本地数据的归属与清理规则明确，不能因登录了另一个账户而泄露共享浏览器的原任务。
- [ ] 同源接口保护、共享持久化配额、并发原子预留、滥用限制与密钥轮换落实；不只靠前端按钮和 Cookie 身份限流。
- [ ] 明确位置/照片/EXIF 的收集目的、保留、删除、导出与共享；不未经同意上传本地存量数据。
- [ ] 滴图账号协议、用途、第三方底图叠加、缓存/导出/展示范围、计费口径及权限已核实。
- [ ] 底图/叠加内容、署名、适用审核/资质要求、服务器地域和数据安全完成专业适用性核查；非商业说明不能替代。
- [ ] 离线能力如有承诺，使用有权离线使用的资源并真实测试；不批量预取 OSM 标准瓦片。
- [ ] 用户明确批准目标环境与一次性发布；有回退方案，才另行执行。

登录和云端同步是独立工程工作包，不属于 FP1 的本地保存承诺。未通过公开门禁时，可保留本机演示，不擅自更换托管商或放开监听地址。
