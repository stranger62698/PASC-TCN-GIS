# 用户数据日期列自动识别

更新：2026-10-16。日期识别已随本机数据处理版发布至正式站点；Python 后台源码同步更新，但当前生产关闭云端数据任务，未部署 Python 后台。

选择 CSV 后，系统读取表头，自动寻找完整年月日观测列、校验实际日历，再按时间先后排列。导入界面显示识别期数与起止日期，用户仍可手动增减时间列。仅识别字段不会运行模型或上传原文件。

## 支持的列名

| 类型 | 示例 |
| --- | --- |
| D 前缀 | `D20240101`、`d20240101` |
| D 加下划线 | `D_20240101`、`d_20240101` |
| 纯数字年月日 | `20240101` |
| 年月日分隔符 | `2024-01-01`、`2024/1/1`、`2024_01_01`、`2024.1.1` |
| 带前缀的分隔日期 | `D_2024-01-01`、`D2024/1/1`、`Date_2024.1.1` |
| 其他明确时间前缀 | `Date20240101`、`Time_20240101`、`T20240101` |

前缀大小写均可，前缀与日期之间兼容空格、下划线、点、横线及斜线。日期年份沿用前端原有的 1900—2099 范围。紧凑日期使用 8 位 `YYYYMMDD`；带分隔符的月、日可为 1—2 位。

同一文件可以混用这些格式，列顺序可以打乱；形变值始终随原列对应日期一起排序，输出日期统一为 `YYYY-MM-DD`。CSV 原文件内容保持不变。

## 无效值与同日列

- `D20230229`、`20241301` 等不存在的日期不计入观测期数；数据接入页保留疑似无效日期提示，手动选中无效日期时确认会报错。
- `point_20240101`、`D20240101_quality` 等描述字段不自动作为观测列。没有完整年月日的月份或日期片段不会被猜测成一天。
- 不同列名表示同一天时按一天处理。同日有效数字必须一致；冲突会阻断导入。主列为空可使用同日有效别名值，全部为空仍为缺测；明确的数字 `0` 是有效观测。
- 清理表头 BOM 和首尾空白，避免字段索引失配；清理后发生同名冲突时明确拒绝。数据单元格与点位身份不会因此改写。
- 手动取消一个日期后不会重新加入该天；仅重复别名不增加有效期数，也不会绕过模型最少有效期数要求。单位、正负号及预处理状态仍由用户确认。

## 验证

- 32 个前端/数据测试入口共 261 项通过，覆盖混合格式、乱序、闰年、无效日期、手动子集、同日冲突、空值与零值、细分流式读取，以及既有地图/本机数据流程。
- Python schema、预处理和模拟任务消费者共 34 项通过，包含混合日期及 BOM/空白表头，没有调用真实模型或网络。
- 浏览器用合成 CSV 验证：6 类混合表头按倒序输入，自动找到 24 期（2024-01-01 至 2024-10-03）；取消首日后变为 23 期，勾回后正确恢复排序；质量检查为 4/4 有效点、24 期、0 无法解析时间字段。没有提交云端保存或运行模型。
- 日期解析与 CSV 解析的定向 TypeScript 检查、修改解析代码和测试的严格 ESLint、静态构建及 Worker 构建通过。页面保留既有 lint/大包警告；不代表全仓类型检查通过。
- 4174 原服务持续运行，页面和新 Worker 可访问，驾车 API 可用；此次日期验证没有新增滴图请求，原进程 HTTP 计数保持 2。
